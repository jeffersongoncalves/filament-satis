title: Tokens
description: Managing authentication tokens for Composer clients.
---

Tokens control which clients can access your private Composer repository and which packages they can pull.

## Creating a Token

Navigate to **Satis > Tokens** and click **Create**.

| Field | Description |
|-------|-------------|
| **Name** | A descriptive label (e.g. `staging-server`, `ci-pipeline`) |
| **Email** | Contact email for this token holder |
| **Packages** | Select which packages this token grants access to |

A unique token value is generated automatically on creation.

## How Authentication Works

Clients authenticate against the Composer API using the token value. Two methods are supported:

### HTTP Basic Auth

```json
{
  "http-basic": {
    "your-app.com": {
      "username": "token",
      "password": "the-token-value"
    }
  }
}
```

### Bearer Token

```bash
composer config bearer.your-app.com the-token-value
```

The `EnsureUserHasLicense` middleware validates the token on every Composer API request and sets the `satis_token` attribute on the request for downstream use.

## Scoped Access

Each token has a many-to-many relationship with packages. When Satis builds, it generates a separate `packages.json` for each token containing only the packages assigned to that token.

This means:
- **Token A** with packages `vendor/core` and `vendor/utils` will only serve those two packages
- **Token B** with package `vendor/admin` will only serve that one package
- Clients using Token A cannot discover or download packages assigned only to Token B

## Revoking Access

To revoke a client's access:
1. Delete the token, or
2. Remove specific packages from the token's package list

After revoking, rebuild with `php artisan satis:build` to regenerate the per-token repositories.
