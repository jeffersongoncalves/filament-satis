title: Webhooks
description: Setting up GitHub webhooks for automatic rebuilds.

Filament Satis can receive GitHub webhook events to automatically trigger repository rebuilds when code is pushed.

## How It Works

Each package gets a unique `reference` code generated on creation. This reference is used in the webhook URL to identify which package triggered the event.

When GitHub sends a webhook payload, the `GithubWebhookController` receives it and dispatches rebuild jobs for the affected package.

## Setting Up a GitHub Webhook

1. **Get the webhook URL** from the package's Integration section in the admin panel. The format is:

   ```
   https://your-app.com/api/satis/webhooks/github/{reference}
   ```

2. **In your GitHub repository**, go to **Settings > Webhooks > Add webhook**

3. **Configure the webhook**:

   | Field | Value |
   |-------|-------|
   | Payload URL | `https://your-app.com/api/satis/webhooks/github/{reference}` |
   | Content type | `application/json` |
   | Secret | The webhook secret from the package's Integration section |
   | Events | Select **Just the push event** |

4. **Save** the webhook

## Webhook Security

Each package has a unique `webhook_secret` generated automatically on creation. GitHub uses this secret to sign the webhook payload, and the controller verifies the signature before processing.

:::caution
Keep webhook secrets confidential. If a secret is compromised, you can regenerate it by updating the package, which will require updating the webhook configuration in GitHub.
:::

## Webhook Flow

```
GitHub push event
  → POST /api/satis/webhooks/github/{reference}
    → Verify webhook signature
      → Identify package by reference
        → Dispatch rebuild jobs
          → Updated packages.json
```

## Troubleshooting

| Issue | Solution |
|-------|----------|
| 401 Unauthorized | Verify the webhook secret matches |
| 404 Not Found | Check the reference code in the URL |
| Build not triggering | Ensure queue workers are running |
| Webhook not received | Check GitHub webhook delivery logs |
